# OpenClawFarm — правила работы

Проект — эксплуатация и развитие «фермы» OpenClaw: сервер **oc-node1** (45.91.237.204) с OpenClaw Gateway,
Nextcloud, BAS-IP Monitor и AI/ML-стеком. Инвентаризация и топология — `docs/Архитектура-и-ресурсы.md`.

## Модель памяти и документации (главное правило)

> **Репозиторий — источник истины. Код — первоисточник. Память агента — тонкий индекс.**

- Всё, что должно пережить диалог, пишем в git-markdown **сразу** («пишу насквозь»), а не только в память.
- Статус — в `docs/СОСТОЯНИЕ.md` (**читать первым каждую сессию**); «почему» — новый/обновлённый ADR;
  долг — `docs/Долги-и-бэклог.md` (со стабильным ID); грабля/инцидент — `docs/Грабли-и-решения.md`.
- **Definition of Done = код + `СОСТОЯНИЕ.md` + запись долга/решения в ТОМ ЖЕ коммите.**
- **Сжатие контекста переносит деталь в док, а не удаляет.**
- Сквозные ID (`ADR-0xx`, долг, `§N.N`, спринт, `ТЗ§x.y`) — ссылаться в коммитах и доках.
- **Типизированная связь между сущностями** → строка `Связи[ИСТОЧНИК]: тип=цель` рядом с фактом в ТОМ ЖЕ
  коммите, затем `python scripts/gen-knowledge-graph.py` (перегенерировать `docs/Граф-знаний.md`, закоммитить).
  Словарь типов и синтаксис — `docs/СВЯЗИ-конвенция.md`. Проверка в хуке: `--check` (падает, если граф устарел;
  включить хук: `git config core.hooksPath .githooks`).
- Факт искать по `docs/` через Grep/Glob (и `docs/ИНДЕКС.md`), **а не по памяти диалога**.

## Дисциплина «пишу насквозь» (обязательна в этом проекте)

**Все данные по проекту и все изменения** (инфраструктура, конфиги, версии, инциденты, решения) фиксируются
в `docs/` сразу после логической единицы работы:

1. Изменение инфраструктуры/сервера → обновить `docs/Архитектура-и-ресурсы.md` (+ версии в `docs/СОСТОЯНИЕ.md`).
2. Новое решение «почему» → `docs/ADR/ADR-0xx-*.md` (не переписывать старые — `supersedes`).
3. Найденный долг → строка с ID `OPF-n` в `docs/Долги-и-бэклог.md`; закрытие → `closes=OPF-n`.
4. Сломалось/починилось → раздел `§N.N` в `docs/Грабли-и-решения.md`.
5. Перегенерировать граф: `python scripts/gen-knowledge-graph.py` и закоммитить всё вместе.

## Связь с сервером (oc-node1)

- Доступ: `ssh root@45.91.237.204` (ключ `rsa-key-20240224` в Pageant) или `ocadmin@` (sudo без пароля);
  пароли SSH отключены (ловушка cloud-init — `docs/Грабли-и-решения.md` §1.1).
- Из Windows-терминала: `plink -ssh -batch root@45.91.237.204 "<команда>"` (Pageant подхватывается автоматически;
  сохранённая PuTTY-сессия — **OpenClawAms**).
- **Под root НЕ вызывать `openclaw`/`oc`** — будет `token_mismatch` (§1.2): сервисные команды — обёртка `oc`
  или `sudo -u openclaw`.
- Эксплуатационный справочник сервера — `/root/RUNBOOK.md` и `/srv/openclaw/RUNBOOK.md` (синхронизация
  с этим репо — долг OPF-3); при расхождении фактов — **сверяться с фактическим состоянием сервера**.
- Секреты (токены, `/etc/openclaw/env`, `secrets/`) **в доки и коммиты не копировать** — только ссылки на место хранения.
- **Правки `openclaw.json` — только через «Фабрику агентов»** (OPF-8, E4): анкета `agents/<id>.yaml`
  → `validate` → `plan` → `apply`; ручные правки конфига запрещены — drift-контроль
  (`export --check`, cron) засигналит (метрика `custom.openclaw.factory.drift`). Деплой factory —
  `scripts/oc-factory-deploy.ps1`; формат анкет и команды — [`agents/README.md`](agents/README.md).

