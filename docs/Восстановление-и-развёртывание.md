## 4. Восстановление данных (restore)

**Где живут данные:** `/srv/nextcloud/pgdata` (БД Nextcloud) + `/srv/nextcloud/html/data`;
`/srv/openclaw/.openclaw` (openclaw.json, agents, extensions, credentials, browser, media);
`/srv/shared/*`; БД BAS-IP Monitor (postgres:16 volume `basip-monitor-postgres-1`);
`/srv/projects/bas-ip-monitor/secrets`. **Точки бэкапов:** `/srv/openclaw/backups/`
(`nextcloud-db`, `basip-git`, `memory-*`, `model-override-*`, `pairing-*`, `upgrade-*`, `skill-*.tgz`)
и `/srv/openclaw/captures`, `/srv/shared/captures`.

**Порядок restore:**
1. Бутстрап §3 (шаги 1–6) → конфиги из `infra/` + секреты из хранилища.
2. Данные: распаковать архивы `/srv/openclaw/backups/auto/<штамп>/` на место
   (`shared.tar.zst` → `/srv`, `openclaw-state.tar.zst` → `/srv/openclaw`, `nextcloud-html.tar.zst` → `/srv/nextcloud`,
   `basip-secrets.tar.zst` → `/srv/projects/bas-ip-monitor`); дампы БД — `pg_restore` из
   `nextcloud-db.dump` / `basip-db.dump` (`-Fc`, `--no-owner`; **роль `oc_admin` создать до restore
   дампа Nextcloud** — на неё завязан `GRANT` в дампе).
3. Стеки поднять (§3 шаги 7–11), конфиги OpenClaw — `.openclaw` целиком; git basip —
   `git clone basip-git.bundle`.
4. Проверка: §5.

**Автоматические бэкапы (OPF-4, развёрнуто 2026-10-14):**

| Компонент | Где живёт | Расписание |
|---|---|---|
| `/usr/local/bin/oc-backup.sh` (копия [`infra/backup/oc-backup.sh`](../infra/backup/oc-backup.sh)) | cron `/etc/cron.d/oc-backup` | ежедневно 03:30 |
| `/usr/local/bin/oc-restore-test.sh` (копия [`infra/backup/oc-restore-test.sh`](../infra/backup/oc-restore-test.sh)) | там же | вс 04:30 |

- Состав одного бэкапа `/srv/openclaw/backups/auto/<штамп>/`: `nextcloud-db.dump`, `basip-db.dump`
  (pg_dump `-Fc`), `shared.tar.zst`, `openclaw-state.tar.zst` (без cache/tmp/logs/npm),
  `nextcloud-html.tar.zst`, `basip-secrets.tar.zst`, `basip-git.bundle` (все refs), `SHA256SUMS`.
- Ротация: последние **5** прогонов (`KEEP` в скрипте); размер прогона ~5.3 GB (~27 GB суммарно).
- Restore-дрель вскрывает свежий бэкап: sha256-манифест, `tar -t` всех архивов, **реальный
  `pg_restore` обоих дампов** во временные postgres-контейнеры (17-alpine / 16-alpine) с подсчётом
  таблиц; контейнеры удаляются, мусора не остаётся.
- Метрики Zabbix (`/var/lib/openclaw-metrics/{backup,restore-test}.json`, ключи
  `custom.openclaw.backup.{status,age_hours,sizeMb}`, `custom.openclaw.restore.status`) —
  [Мониторинг-и-алерты.md](Мониторинг-и-алерты.md). Первый прогон и restore-дрель 2026-10-14 —
  `status=ok` (nextcloud 135 таблиц, basip 66).

## 7. Docker-ландшафт и правила ad-hoc контейнеров (OPF-1/OPF-2, закрыты 2026-10-14)

**Штатные стеки (не трогать без нужды):**

| Контейнеры | Проект | Где живёт |
|---|---|---|
| `basip-monitor-{app,postgres,caddy}-1` | compose `basip-monitor` | `/srv/projects/bas-ip-monitor` (Makefile, `docker/docker-compose.yml`) |
| `nc-{app,db,redis,push,cron}`, `caddy` | Nextcloud + edge | `/srv/nextcloud`, `/srv/caddy` |

**Правила (зафиксированы при разборе OPF-1/OPF-2):**

- Тестовые прогоны — **не долгоживущими контейнерами**: `make test` / CI в `/srv/projects/bas-ip-monitor`;
  если нужен разовый контейнер — `docker run --rm` и не оставлять на ночь.
- Ad-hoc захваты/эксперименты (RTSP и т.п.) — host-скрипты и данные в `/srv/openclaw/captures`
  (или `/srv/shared/captures`); регулярные задачи — cron/systemd/compose, не ручные `docker run`.
- Перед удалением — инвентаризация: `docker ps -a`, `docker inspect <имя> | jq -c .[0].Config.Cmd,…`
  (проверить тома и порты; контейнеры без томов удалять безопасно).
- 2026-10-14: удалены `epic_lovelace`, `intelligent_carver` (pytest-прогоны от 2026-09-25, без томов);
  `rtsp_capture_20261014` — разовый эксперимент, к разбору уже отсутствовал. Образы
  `basip-test:local`, `basip-migration-test-app`, `basip-smoke-app` (~2.9 GB) оставлены —
  кандидаты на `docker rmi` (решение за владельцем).

## 8. Источник истины и синхронизация RUNBOOK (OPF-3, закрыт 2026-10-14)

- **Источник истины — git-репозиторий OpenClawFarm (`docs/`)**. Серверные копии
  `/srv/openclaw/RUNBOOK.md` (1758 строк) и `/root/RUNBOOK.md` (162 строки) — исторические журналы;
  2026-10-14 в `/srv/openclaw/RUNBOOK.md` добавлен заголовок-указатель на репо.
- **Снимок на дату переноса:** [`archive/RUNBOOK-oc-node1-20261014.md`](archive/RUNBOOK-oc-node1-20261014.md)
  (секреты замаскированы, значения не выгружались).
- **Известный дрейф старого текста:** модельная цепочка описана как `anthropic/claude-opus-5`
  (резерв haiku-4-5) — фактически DeepSeek через polza ([ADR-004](ADR/ADR-004-model-chain-deepseek-polza.md)).
- **Процедура досинхронизации** (после крупных изменений на сервере или раз в квартал):
  1. Снять raw-байты: `cmd /c 'plink -ssh -batch root@45.91.237.204 "cat /srv/openclaw/RUNBOOK.md" > tmp-runbook.md'`.
  2. Замаскировать секреты: `powershell -File scripts\mask-secrets.ps1 -In tmp-runbook.md -Out tmp-runbook-masked.md`
     (значения не выводятся; **сырой файл не коммитить и удалить сразу** — см. грабли §1.5 про кодировки).
  3. Контроль в выводе скрипта: `bot-token/anthropic/polza/jwt/privkey` = 0; `bare-secret` ≤ 1 допустим
     (ложное срабатывание на сниппетах прав `root:группа`).
  4. Обернуть заголовком (дата, источник истины, дрейф) → `docs/archive/RUNBOOK-oc-node1-<дата>.md`,
     обновить [`ИНДЕКС.md`](ИНДЕКС.md) и закоммитить всё вместе с перегенерированным графом.
