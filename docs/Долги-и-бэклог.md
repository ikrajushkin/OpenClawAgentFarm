## OPF-4 — описания недостаточно для полного восстановления сервера «с нуля»

- **Статус:** 🟡 открыт (аудит достаточности 2026-10-14)
- **Что:** текущая база знаний — «карта местности» (топология, версии, решения), достаточная для понимания
  и частичного провижининга (VM, ОС, схема сервисов), но **не для развёртывания полной копии**. Не хватает
  (помимо секретов):

     `/srv/shared`, состояние `/srv/openclaw/.openclaw` (агенты, расширения, cron, память), а также
     **процедур бэкапа/восстановления** (сами бэкапы в `/srv/openclaw/backups` не описаны).
  2. **Конфигов целиком:** `openclaw.json`, compose-файлы (Nextcloud, Caddy, BAS-IP), netplan
     (`60-gre-lab.yaml` — GRE-туннель!), fail2ban jails, zabbix-agent, `01-hardening.conf` (sshd),
     non-secret-часть `/etc/openclaw/env`, occ-конфигурация Nextcloud (trusted domains, memcache, notify_push).
  3. **Сборки образов:** Dockerfile `nextcloud-shared:34`, `docker/Dockerfile` + `docker-compose.yml`
     BAS-IP Monitor — фактически весь код `/srv/projects/bas-ip-monitor` как субпроект.
  4. **Пинов версий:** digest образов (теги плавающие), patch-версии Nextcloud/приложений, версии
     whisper.cpp/piper/parakeet/ollama.
  5. **Процедур:** DNS-зоны `paylama.tech`/`paylama.online`, файрвол провайдера (Timeweb), порядок
     бутстрапа хоста (пользователи, группы, sudo, UMask), регистрация Telegram-бота, апгрейды.
  6. **Знаний из серверного RUNBOOK** (1758 строк) — см. OPF-3.
- **Что сделать (чек-лист; ✅ — сделано 2026-10-14):**
  - [x] завести [`Восстановление-и-развёртывание.md`](Восстановление-и-развёртывание.md) (бутстрап «с нуля» + restore + чек-лист проверки);
  - [x] выгрузить non-secret конфиги в `infra/` (systemd, caddy, nextcloud, basip-monitor, netplan, ssh,
    fail2ban, sudoers, openclaw env, zabbix) с масками секретов;
  - [x] зафиксировать digest-ы образов (`infra/versions/docker-images-digests.txt`) и версии рантаймов

  - [ ] автоматизация регулярных бэкапов + прогон restore «на зелёном поле»;
  - [ ] IaC (Terraform/Ansible) вместо ручного бутстрапа;
  - [ ] доступы к DNS-зонам и файрволу Timeweb (вне репо — только ссылки);
  - [ ] пины сборок piper / parakeet / whisper.cpp.

## OPF-5 — находки `oc security audit` не закрыты (1 critical, 2 warn)

- **Статус:** ✅ закрыт 2026-10-14 (обнаружено 2026-10-14, см. [Оркестрация-агентов.md](Оркестрация-агентов.md))
- **Что:** (1) CRITICAL — `plugins.allow` не задан, глобальные extensions (`duckduckgo`, `max`) грузятся
  без allowlist; (2) WARN — нет `gateway.auth.rateLimit` при bind не loopback (172.18.0.1); (3) WARN —
  плагин `signal` без integrity-метаданных. Плюс: `tools.elevated` включён без политики approvals.
- **Что сделать:** задать `plugins.allow`; `gateway.auth.rateLimit` (напр. 10 попыток/60с, lockout 300с);
  переустановить или удалить signal-плагин; настроить approvals-allowlist для exec.
- **Критерий:** `oc security audit` — 0 critical / 0 warn.
- **Решение (2026-10-14):** задан `plugins.allow` — 20 доверенных id (signal и неиспользуемые
  provider/инструментальные плагины исключены); `gateway.auth.rateLimit = {maxAttempts:10, windowMs:60000,
  lockoutMs:300000}`; плагин `@openclaw/signal` **удалён** (`oc plugins uninstall signal --force` —
  вместе с install-записью, это закрыло и WARN про integrity); конфиг приведён к `openclaw:openclaw 600`
  (попутно закрыт CRITICAL `fs.config.perms_world_readable`, появившийся после правки — см. §1.3).
  Факт: `oc security audit` → **0 critical · 0 warn · 2 info** (info: сводка поверхности атаки,
  «DM MAX заперты» — это политика pairing, не находка). Вне критерия осталась политика approvals для
  `tools.elevated` — перенесена в план развития ([Оркестрация-агентов.md](Оркестрация-агентов.md) §4.6).

## OPF-6 — нулевая наблюдаемость использования моделей

- **Статус:** 🟡 открыт (частично закрыт 2026-10-14; обнаружено 2026-10-14)
- **Что:** `oc gateway usage-cost --all-agents --days 7` показывает **$0.00 / 0 tokens** — учёт расхода
  polza-провайдеров не работает; метрики Gateway/агентов не выгружаются в уже установленный Zabbix.
- **Уточнение (2026-10-14):** `$0.00` — **артефакт plain-вывода** (дезинформировал); `--json` показывает
  реальный учёт (за 2026-10-14: 6.72M токенов, $36.35, из них cacheRead 4.55M). Метрики выгружены в
  Zabbix: cron `*/10` (`/usr/local/bin/openclaw-usage-refresh.sh` → `/var/lib/openclaw-metrics/usage.json`,
  копия `infra/openclaw/usage-refresh.sh`) + UserParameter `custom.openclaw.usage.{cost,tokens,input,output,
  cache_read}` (`/etc/zabbix/zabbix_agentd.d/openclaw.conf`, копия `infra/zabbix/openclaw-usage.conf`,
  cron-юнит `infra/cron/openclaw-metrics`); проверено `zabbix_agentd -t` (cost=36.35, tokens=6720959).
- **Остаток:** создать элементы данных и алерты на стороне Zabbix-сервера (92.53.116.x — вне этого хоста);
  алерты на error-прогоны cron и падение Gateway.

## OPF-7 — консистентность и живость агентского контура

- **Статус:** 🟡 открыт (частично закрыт 2026-10-14; обнаружено 2026-10-14)
- **Что:** (1) `heartbeat:main` падает (`agent-runner-failure`) — контроль живности агентов сломан;
  (2) канал Signal включён, но not configured/stopped — мёртвый шум в статусах; (3) workspace агента
  `ksu` — `~/workspaces/Ksu`, вне `/srv/shared` (вопреки ADR-003, вне общей зоны бэкапов);
  (4) идентичности из разных источников (config vs IDENTITY.md); (5) схема ключей polza vs polza-ksu
  (разделение расходов?) не зафиксирована в ADR.
- **Что сделать:** `oc doctor` + `oc cron runs` по heartbeat:main; выключить/поправить Signal; перенести
  workspace ksu в `/srv/shared/Projects/Ksu`; дописать в ADR-004 схему ключей.
- **Прогресс (2026-10-14):** (1) heartbeat:main — сбой был **разовым** (14.10 06:07, `agent-runner-failure`
  в момент смены токенов/моделей); ручной прогон `oc cron run 6d5c36dd… --wait` → `succeeded`
  («heartbeat completed»), расписание daily работает → закрыто; (2) Signal закрыт: плагин удалён
  (OPF-5), в `channels list` канала нет, строка в `channels status` — лишь заглушка каталога → закрыто.
- **Остаток:** (3) workspace ksu → `/srv/shared/Projects/Ksu`; (4) унификация идентичностей;
  (5) схема ключей polza vs polza-ksu — дописать в ADR-004 (датированное дополнение).
