## 2. Что показала индустрия

### 2.1 ClawHub — маркетплейс skills/плагинов (главная находка)

`clawhub.ai` — публичный реестр OpenClaw-пакетов: skills (версионируемые бандлы `SKILL.md` + файлы)
и code-плагины. Установка нативная: `openclaw skills search|install|update`, `openclaw plugins install <pkg>`.
Семвер, теги, чейнджлоги, **security-scan summaries на странице пакета**, модерация, репорты.
Публикация своих — `clawhub skill publish ./dir` (нужен `npm i -g clawhub`, аккаунт).

Live-проверка с oc-node1 (`openclaw skills search calendar`): каталог живой — Google Workspace
(Gmail/Calendar/Drive), CalDAV-календари (в т.ч. **Nextcloud**), календари Outlook/Lark и др.
Вывод: часть того, что мы делаем/планируем сами, в мире уже упакована; и наши навыки можно
публиковать наружу.

### 2.2 Мультиагентные паттерны: команды и «дорожки»

- **`openclaw agents team create`** — готовый пресет команды: coordinator / researcher / writer /
  reviewer с lane-контрактами в `AGENTS.md` (Owns / Non-goals / Chat budget / Handoff / Tool posture)
  и подключением координатора к специалистам.
- **Parallel specialist lanes** (доки OpenClaw) — методика распараллеливания работ без засорения
  общих очередей: сначала контракты дорожек, потом `maxConcurrent`/`subagents.maxConcurrent`/очередь
  (`messages.queue: {mode, cap, drop}`), координатор — последним.
- **Sub-agents** — развитый механизм: свои сессии `agent:<id>:subagent:<uuid>`, `context: "fork"`,
  вложенность с политикой по глубине, `delegationMode`, отдельная модель субагентов
  (`agents.defaults.subagents.model`) — рекомендуют держать дешёвую модель для тяжёлых задач.

### 2.3 Память: tiers, dreaming, wiki, provenance

`memory-core` (включён) устроен как многоуровневая система: Instructions → Curated core
(`MEMORY.md`/`USER.md`) → Episodic (дневники `memory/YYYY-MM-DD.md`) → Prospective (standing intents).
Ключевые фичи:
- **Dreaming** (включён по умолчанию, cron 03:00) — ночная консолидация light→REM→deep с промоушеном
  сильных сигналов в `MEMORY.md`, `DREAMS.md`-диарием, защитой от засорения (пороги, preimages, undo).
- **Provenance** — защита от poisoning: происхождение записей фиксируется на записи; untrusted-контент
  никогда не получает инструкционной власти. Прямо перекликается с нашим навыком «Безопасность».
- **active-memory** (core-плагин) — ограниченный pre-reply retrieval; **memory-wiki** — компилируемая
  вики (synthesis/entity/concept-страницы) с импортом истории (`openclaw wiki chatgpt import`).
- CLI-управление: `openclaw memory promote [--apply]`, `promote-explain`, `rem-harness`, `status`.

### 2.4 Эффективность (наш «болевой» пункт — токены/скорость)

- **tokenjuice** (плагин) — компактит результаты `exec`/`bash` (у нас tool-результаты — главный
  потребитель контекста после транскриптов).
- `tool-search`, `trajectory`, `loop-detection` — штатные инструменты контроля объёма и циклов
  (наш инцидент skill-workshop 22.10 — ровно этот класс проблем).
- Практика субагентов: тяжёлую работу выносить в дешёвые модели/фоновые запуски.

### 2.5 Безопасность исполнения

- **Sandboxing** (по умолчанию выключен!) — режимы `off`/`non-main`/`all`, scope `session`/`agent`/`shared`,
  бэкенды Docker/Podman/SSH/OpenShell/Crabbox; `openclaw sandbox list|explain|recreate`.
  Сейчас инструменты всех агентов исполняются на хосте — это главный реальный риск фермы.
- `exec`-approvals, permission-modes, `tools.elevated` (глобальный + per-agent гейты),
  `openclaw security audit`, managed GitHub identity с явным opt-in в песочницу.

### 2.6 Связность: A2A, MCP, ACP

- **A2A-канал** (в core-плагинах): `/.well-known/agent-card.json`, bearer-токены на пира,
  `SendMessage` JSON-RPC, `exposeAgents` — готовый способ связать нашу ферму с другими
  агентами/фермами (стандарт Linux Foundation).
- **MCP**: `openclaw mcp serve` — экспонировать сессии OpenClaw как MCP-сервер для внешних клиентов
  (Claude Code/Codex); CLI Backends (MCP bridge) — использовать локальный AI CLI как runtime.
- **ACP** (Agent Client Protocol): подключить внешние coding-харнесы (Claude Code, Cursor, Copilot,
  Droid, Gemini CLI, OpenCode) как рабочие лошадки через `sessions_spawn({runtime:"acp"})`, `/acp`.
- Отдельно: **Codex** — нативный app-server плагин (`/codex bind`), **advisor** (experimental) —
  ревью работы агента его же моделью с одной коррекцией.

### 2.7 Операционная зрелость

Release channels (`stable`/`dev`), авто-обновления + rollback и recovery, `openclaw doctor --fix`,
managed worktrees (изолированные git-чекауты со снапшотами), Cloud Workers (одноразовые облачные
машины для тяжёлых задач), hooks/standing orders/taskflow/webhooks/Gmail PubSub в автоматизациях.

### 2.8 Внешние мультиагентные фреймворки (LangGraph / AutoGen / CrewAI / OpenAI Agents SDK)

Вывод обзора: для нашей фермы они **не нужны как ядро** — мы уже на специализированном self-hosted
стеке (OpenClaw) со своими каналами/сессиями/памятью. Релевантно лишь: паттерны (lane-контракты,
handoff-саммари — уже приняты в доках OpenClaw) и, при появлении внешних систем, связка через
**A2A/MCP**, а не миграция.

## 3. Направления развития

| # | Направление | Готовое решение | Ценность | Усилия |
|---|---|---|---|---|
| N1 | Экосистема вместо велосипедов | ClawHub skills/плагины | Высокая | Низкие |
| N2 | Команда специалистов (lanes) | `agents team create`, subagents-конфиг | Высокая | Средние |
| N3 | Память 2.0 | memory-core: dreaming, wiki, provenance | Средняя | Средние |
| N4 | Токены и скорость | tokenjuice, tool-search, loop-detection | Высокая | Низкие |
| N5 | Песочницы и safety | sandboxing (Docker), approvals, `security audit` | Высокая | Средние |
| N6 | Связность ферм | A2A, `openclaw mcp serve`, ACP | Средняя | Средние |
| N7 | Операционная зрелость | release channels, rollback, doctor, worktrees | Средняя | Низкие–средние |
| N8 | Автоматизации глубже | standing orders, taskflow, webhooks | Средняя | Низкие |

**N1. Экосистема ClawHub.** (а) Разведка каталога под наши сценарии: Nextcloud/Nextcloud Talk
(у нас Nextcloud 34!), почта, календари, безопасность — ставить только проверенное, с пином версий
и `plugins.allow` (наш грейт уже включён). (б) Публикация **своих** навыков («Безопасность», база
знаний, `/проект`, `/фон`) через `clawhub skill publish` — они станут переиспользуемыми пакетами
и дистрибуцией между фермами; фабрике добавить шаг «упаковка навыка». Первый шаг: `openclaw skills
search <тема>` по 3–5 темам, свести таблицу «есть готовое vs пишем сами».

**N2. Команда lanes.** Формализовать роль-модель фермы по готовому пресету: coordinator/service —
исполнительские дорожки (researcher/writer/reviewer уже частично есть: писатель ksu). Lane-контракты
(Owns/Non-goals/Chat budget/Handoff/Tool posture) генерировать из анкет — это прямое расширение
фабрики (новый блок анкеты → `AGENTS.md`). Субагентов оформить конфигом: `subagents.model`,
`delegationMode: "prefer"`, `maxConcurrent`, `context:"fork"` — вместо мягкого правила в AGENTS.md,
которое модель игнорирует (урок 22.10). Первый шаг: пресет `agents team create` в тестовом агенте.

**N3. Память 2.0.** Проверить фактическое состояние dreaming (`/dreaming status`), включить
promote-процесс; пилот memory-wiki на `service` (компиляция знаний проектов — смыкается с нашим
PROJECT.md/docs). Provenance-модель — теоретическая база для навыка «Безопасность» (untrusted-контент
не получает инструкций). Осторожно: не смешивать с ручной `MEMORY.md` без правил (dreaming имеет
undo/preimages).

**N4. Токены и скорость.** Поставить `tokenjuice` (компакт exec-результатов — наш главный пожиратель
контекста), оценить `tool-search`; включить/проверить `loop-detection` (страховка от повтора
инцидента skill-workshop). Компакт сессий (`sessions compact`) уже работает — закрепить регламент
(порог ~300K → компакт). ✅ **2026-10-23: сделано** — tokenjuice установлен (совместимая версия
2026.8.2, авто-подбор) и включён, `tools.loopDetection.enabled=true` (hot-reload), toolSearch —
unset (авто-structured, не трогали). Smoke-тест пройден; замер экономии — по `usage-cost` за
1–2 дня. Остаток: регламент компакта сессий.

**N5. Песочницы.** Пилот sandbox `non-main` на `service` (Docker-бэкенд, scope `session`), затем
раскатка; `openclaw security audit` — как регулярная проверка. Песочница — не идеальная граница,
но материально ограничивает ущерб при «глупости» модели.

**N6. Связность.** A2A-канал: связать фермы (например, рабочий кластер + домашний) или открыть
ограниченный API для внешних агентов (bearer-токены на пира, `exposeAgents`). `openclaw mcp serve` —
как вход для IDE/внешних клиентов. ACP — опционально: использовать Claude Code/Codex как харнесы
для тяжёлых coding-задач.

**N7. Операционка.** Перевести апдейты на release channels + авто-обновление с rollback (сейчас
ручные патчи `openclaw.json` — рискованный процесс, грабли §1.3/§1.7); `doctor --fix` в регламент;
managed worktrees — для работ с кодом на сервере.

**N8. Автоматизации.** Помимо дайджеста: standing orders («постоянные поручения»), taskflow, webhooks
(внешние события будят агента), Gmail PubSub — расширение слоя `reports`/`фон` фабрики.

## 5. Риски и ограничения

- **ClawHub открыт по умолчанию** (публикация — с гейтом GitHub-аккаунта): ставить пинённые версии,
  смотреть scan-сводки, держать `plugins.allow`; «установка плагина = запуск кода» (доки OpenClaw).
- **Автономные процессы** (advisor, dreaming, skill-workshop) — после инцидента 22.10 включать
  пошагово, с мониторингом и возможностью выключить одной строкой.
- **Память:** авто-промоушен может раздуть `MEMORY.md` — у dreaming есть пороги, но пилот обязателен.
- **Ресурсы oc-node1:** Docker-песочницы и очереди — нагрузка на один сервер (см.
  [Архитектура-и-ресурсы.md](Архитектура-и-ресурсы.md)).
- **Не делать:** не мигрировать ядро на внешние фреймворки (LangGraph и пр.), не публиковать в ClawHub
  пакеты с секретами/боевыми ключами.
